# 平台适配：自然语言成品提示词的投放参考

## 一、适用范围与证据边界

本文件配合 `01-风格锁核心.md`、`03-图像提示词语法.md`、`04-视频提示词语法.md` 使用。**只适配投放方式，不改变十条核心锁，不绑定任何题材。** 英文为提示词主干；素材引用标记可保留平台要求的形式。

**所有参数以当前官方文档为准。** 模型版本、快慢变体、API、网页端及第三方封装可能不同。本文区分：①官方文档或官方 SDK 已确认的接口能力；②本技能的投放建议；③查不到可靠依据的 **未核实** 项。官方 SDK 是参数来源，不等于完成了实际付费生成测试。搜索到页面标题而未取得参数正文，也不算参数已核实。

| 通用规则 | 执行方式 |
|---|---|
| 成品而非零件 | 保留一条可投放的完整提示词；仅平台确有独立负向字段时拆出负向文本。参数设置单独说明，不混进正文伪装成画面元素。 |
| 参数优先 | 比例、时长、输出尺寸优先用接口或界面设置。正文中的 `21:9`、秒数是语义请求，不能突破接口枚举或保证实际输出。 |
| 超宽不等于超广角 | `21:9` 描述画布；35–85mm、远机位、水平地平线描述透视。不要用 `ultra-wide lens` 换取超宽画布。 |
| 压缩不删锁 | 先删质量口号、同义反复、无关背景和多余镜头；合并相关约束，不删除尺度标尺、庇护形态、克制机位、溢框占位、透光、配色比例、负空间、等比纹理、唯一焦点、安全情绪。 |
| 视频逐镜继承 | 每镜写明继承全局视觉系统；跨请求生成时，必须把全局锁重新写全，不能让用户自行复制拼装。 |
| 参考图不是硬保证 | 上传素材后明确各自只负责构图、材质或配色；拒绝把参考图中的题材当成风格。参考图、首帧和尾帧不是同一种输入。 |

### 21:9 决策速查

| 模型 | 本次核实的 21:9 结论 | 投放动作 |
|---|---|---|
| Seedance 2.0 | **未核实**：找到官方接口入口，但未取得对应参数正文 | 不凭其他版本或第三方说明提交 `ratio=21:9`；先检查当前入口 |
| Seedance 2.5 | **未核实**：官方系列说明已找到，具体比例仍未取到依据 | 与 2.0 分别核对，不能自动继承 |
| H3 | **支持**；图生视频的比例由输入图决定 | 文生／参考生用 `ratio="21:9"`；图生使用目标比例首尾图并核查结果 |
| Wan 3.0 | 显式比例枚举**不含 21:9**；`adaptive` 能否精确保留超宽 **未核实** | 不提交非法枚举；必要时采用明确标注的裁切交付 |
| GPT Image 2 | **支持表达精确 21:9 的自定义尺寸**，仍须满足当前尺寸约束 | Images API 用 `size="2016x864"`，不是 `aspect_ratio` |
| GPT Image 2.5 | 已核实的具体变体支持同类自定义尺寸 | 确认具体模型标识后用 `size="2016x864"` |
| Nano Banana Pro | 官方指南明确给出 **21:9** 构图用法 | 有比例配置时优先配置；对话端自然语言请求后检查实际尺寸 |
| Nano Banana 2 | 官方说明继承已有比例并增加超长比例；通用文档列有 **21:9** | 使用当前 Gemini 图像比例配置，不套用旧 Nano Banana 的限制 |
| Midjourney | 通过自定义宽高比参数表达 **21:9** | 提示词末尾 `--ar 21:9`；可约分为 `--ar 7:3`，以当前模型比例限制为准 |

**非原生超宽的兜底不是原生支持。** 若只能生成 16:9，可预留上下裁切安全区，再裁成 21:9；同宽裁切保留原高度的 16/21，即上下合计约裁去 23.8%。参照物、接触阴影、透光边缘和唯一焦点必须落在保留区。裁切后按最终画面重新检查占位与负空间比例。加黑边只改变封装观感，不能补出横向内容，也不能冒充原生超宽构图。

## 二、视频模型

| 项目 | 适配说明 |
|---|---|
| 提示词形态与长度 | 本技能建议采用完整自然语言：全局视觉系统 → 分镜或连续运动 → 全局约束。避免散乱标签和无意义质量词。官方最优长度、硬性字符上限均 **未核实**，不填猜测数字。 |
| 负向约束 | 当前对应接口是否提供独立负向字段 **未核实**。安全投放为把负向改写成正向结果，如 `stable level camera, softly luminous edges, readable grey shadows, calm sheltering forms`；不使用 Midjourney 的 `--no`。 |
| 画幅／比例 | 21:9、完整比例列表、比例参数位置以及图生时的继承规则均 **未核实**。以当前官方接口和实际界面为准；正文写超宽构图不能证明输出为 21:9。 |
| 首帧／尾帧／参考图 | 本次未取得足够正文，三种能力的具体输入字段、数量、互斥规则和引用语法均 **未核实**。入口确认支持后先上传并绑定角色，再在正文说明“从已绑定首帧开始，保持其尺度与照明”；仅写“参考图一”不会自动上传素材。 |
| 本技能投放要点 | 从 `04` 的单镜路线起步，保留全部十锁及起终状态；若入口长度不足，先减少镜头，不砍透光与尺度对照。总时长必须采用当前入口允许值，不照抄旧表中的常见上限。 |
| 特有风险与坑 | 产品入口、海外接口、第三方同名服务不等价；不要因网页标题含模型名就认定是官方。自动扩写若可关闭，可对完整成品关闭后测试；具体开关 **未核实**。不要擅自写入素材标签或 API 字段。 |

| 项目 | 适配说明 |
|---|---|
| 提示词形态与长度 | 建议完整英文自然语言；分镜采用明确的时间顺序与单一主运镜。长度倾向为“信息齐全、无重复”，官方最优字数及字符上限 **未核实**。 |
| 负向约束 | 独立负向框／字段 **未核实**，默认采用正向句式并入正文。将“不要猛烈推进”改成“缓慢匀速推进并保持参照物可辨认”，不转移成恐怖气氛词列表。 |
| 画幅／比例 | 21:9 支持、比例枚举、设置字段、界面选项和图生优先级均 **未核实**。不能因版本更新就声称支持任意比例。 |
| 首帧／尾帧／参考图 | 对应模式是否支持、允许组合、素材数量与正式引用语法均 **未核实**。经入口确认后明确素材职责；若没有首尾帧模式，不把两张参考图描述为必达的首尾关键帧。 |
| 本技能投放要点 | `04` 中每镜都回指同一视觉系统；若长镜头超过可用上限，输出多条各自完整的分段提示词。续接时重写锁，保持亮度、色相、尺度、接触关系连续。 |
| 特有风险与坑 | “新版本可生成更长视频”不能推导为本账号或当前入口已开放相同时长；原生音频、时长和扩写开关也需单独核对。不要把一个版本的自动扩写、素材语法或默认比例复制给另一个。 |

### 3. H3（本平台）

官方来源：[视频生成 V2 创建任务](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create)、[同页官方 Markdown／OpenAPI schema](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md)。以下针对文档中的 `MiniMax-H3`；不得混用 H3 Max 或旧版接口参数。

| 项目 | 适配说明 |
|---|---|
| 提示词形态与长度 | 支持多模态 `content` 数组，所有模式都必须有非空文本项；单个 `text` 最多 **7000 字符**。建议把 `04` 的完整自然语言放进文本项，清楚分镜、动作和运镜；上限不是推荐写满的长度。[官方 schema](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md) |
| 负向约束 | 已核实的 V2 schema **未列独立负向字段**，也没有 `--no` 语法。将禁用项转为正向稳定条件并入 `text`；不要自行添加旧接口或第三方的 `negative_prompt`。[官方 schema](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md) |
| 画幅／比例 | `ratio`：`adaptive`、`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`。**文生视频必填具体比例，不能为 adaptive**；参考生视频可显式设 `21:9`；**首尾帧图生时具体 ratio 会被忽略，恒按 adaptive，比例由输入图决定**。[官方 schema](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md) |
| 首帧／尾帧／参考图 | 图片项用 `role=first_frame`、`last_frame`、`reference_image`；首尾各最多一张，参考图最多九张。首尾帧模式与任何参考图片／视频／音频模式互斥。正文说明绑定图的用途，例如首帧保持构图、尾帧完成尺度揭示；参考素材编号的精确解析语法 **未核实**，不自造特殊标签。[官方 schema](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md) |
| 本技能投放要点 | H3 文档时长 **4–15 秒整数**、输出 `768P`／`2K`。先由 `03` 制作同一比例且全部十锁成立的首尾图，再用 `04` 只组织合理的连续运动并重申全局锁。首尾的巨物占位不能因“揭示全貌”变成完整小模型。[官方 schema](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md) |
| 特有风险与坑 | 图生传 `ratio="21:9"` 不代表已强制超宽，必须检查输入和输出。官方 schema 对单独尾帧存在表述冲突：输入组合允许仅尾帧，而 `role` 注释称尾帧需与首帧配对；本技能优先成对使用，尾帧独用 **未核实**。`extra.prompt_expansion_mode` 被说明为 H3 Max 专用，不能套到 H3。 |

| 项目 | 适配说明 |
|---|---|

| 负向约束 | 本次核实的 3.0 请求字段**未列 `negative_prompt`**。用正向结果并入 `prompt`，不要把旧代 Wan 的独立负向能力迁移过来。第三方负向框是否实际传给模型 **未核实**。[官方 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference) |
| 画幅／比例 | `parameters.ratio` 列出 `adaptive`（默认）、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`；**没有 21:9 显式枚举**。输入图可接受超宽，不代表输出一定保留同一比例；`adaptive` 精确保留 21:9 **未核实**。必须验证实际宽高，或使用前述 16:9 裁切方案并如实标注。[官方 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference) |
| 首帧／尾帧／参考图 | `input.media` 用 `type=first_frame`／`last_frame`／`reference_image`，首尾各一张，参考图最多十张。已列组合为首帧或首帧加尾帧；首尾模式与参考媒体互斥。参考模式按媒体种类分别编号，可用官方示例形式 `图1`、`视频1`、`音频1`；英文主干中保留这些引用即可。[官方 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference) |

| 特有风险与坑 | `audio` 默认 `true`；不要声音时设 `false`，要声音则写克制环境音。参考图的高饱和区域可能被继承，先在图像阶段校验。首尾图不能同时混入参考音频；单独尾帧未出现在允许组合中，不视为已支持。[官方 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference) |

## 三、图像模型

> 以下五节讨论静态图生成。首帧／尾帧在这里是“生成后可供视频模型使用的图”，不是图像接口自动提供视频时间边界。不要把 `04` 的多个镜头整段交给图像模型期待输出视频；应按 `03` 为每一张关键帧输出独立完整成品。

### 5. GPT Image 2

官方来源：[OpenAI 图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)、[图像编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)、[官方 Python SDK 生成参数定义](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py)。官网正文访问受限时，尺寸与文本长度采用成功取得的官方 SDK schema，而非第三方教程。

| 项目 | 适配说明 |
|---|---|
| 提示词形态与长度 | API 的 `prompt` 是图像文本描述；GPT 图像模型最长 **32000 字符**。本技能建议完整自然语言，保留 `03` 十槽，将尺度关系和材质写成因果明确的句子；无需压成标签串。该上限仅指已核实 Images API，不代表对话界面。[官方 SDK](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py) |
| 负向约束 | 已核实生成 schema 无独立负向字段；不支持 Midjourney `--no`。自然语言可说明排除项，但本技能优先改为正向目标，如通透中灰暗部、天然微结构和稳定透视，并入成品正文。[官方 SDK](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py) |
| 画幅／比例 | GPT Image 2 支持 `size="宽x高"` 自定义尺寸；宽高都需为 **16 的倍数**，比例在 **1:3 至 3:1**，还需满足当前像素和边长限制。可用 **`2016x864` 精确表达 21:9**；这是由规则推导的设置示例，不是生成实测。支持常规方形／横向／竖向，不限于旧模型三档。[官方 SDK](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py) |
| 首帧／尾帧／参考图 | 静态图不适用首尾帧控制；官方提供图像编辑入口，可随图说明“保留第一张图的构图，仅调整透光边缘”。本次未完整取得编辑参数正文，具体上传字段、张数和保真开关 **未核实**，以当前编辑文档为准。[官方编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit) |
| 本技能投放要点 | `03` 可整体投放；将尺寸从风格描述中移至设置。正文仍说明横向庇护结构、溢框和负空间，避免“尺寸正确但构图是普通横图”。修改时同时重申尺度、占位和配色比例，不能只说“更宏大”。 |
| 特有风险与坑 | 旧版只支持固定尺寸的结论不适用此模型；但自然语言要求尺寸也不能代替 API 的 `size`。SDK 提醒高尺寸存在实验性质与额外限制，不把“任意尺寸”解释为无限画布。对话端和 Responses 工具是否暴露同样尺寸选项 **未核实**。[官方 SDK](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py) |
